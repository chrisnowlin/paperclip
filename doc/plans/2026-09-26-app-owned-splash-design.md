# App-owned Splash runtime for Standalone V2

Status: implementation design · 2026-09-26

## Decision

V2 bundles the installed Splash 1.0.2 program files, including its Python and native engine, but not the 16 GiB model weights. Paperclip starts and stops the bundled Splash server as a child of its own server process. The existing Hugging Face snapshot supplies `incoai/Qwen3.8-27B-Splash` offline. Bionic/LM Studio is no longer an inference dependency. No model download or provider-account fallback is permitted.

Keep the persisted adapter type `lmstudio_splash_local` so the already-created CTO, Coder, and Splash Local agents remain usable. Rename its user-facing label to **Splash (app-managed)**. The fixed API route moves to `127.0.0.1:3321`; the launch adds the legacy `qwen3.8-27b-splash` alias while `/status` must identify the canonical `incoai` package. This port is private to V2 and does not change V1/V2 app, API, database, or data-directory identities.

## Lifecycle and authority

An instance-admin board action can prewarm Splash; another action stops it. A local Splash task wake also starts the bundled model on demand so persisted work and watchdog reviews can survive an app restart or an idle unload without board intervention. The settings probe reports an unloaded model as a warning and does not start it. Starting checks at least 8 GiB of disk headroom, the existing local snapshot, the bundled executable, port ownership, and known external local-model listeners. It sets Hugging Face offline mode and launches the fixed model with a 28 GiB Metal ceiling, bounded context, no web UI, and a fixed loopback bind. Readiness verifies `/ready`, `/status.instance.model`, and the Splash-owned model alias. Repeated starts coalesce and never create a second instance. Stopping refuses while a Paperclip Splash run is active; orderly V2 shutdown stops its child after runs drain. If the child exits unexpectedly, the next local task wake or explicit Start can recover it. Startup failures surface on that run and never select a paid provider.

The bundle uses V2-owned writable runtime/model-link state and the existing Hugging Face cache. It links the cached revision into its private home and seeds Splash's model catalog locally before launch, so the launcher does not query the Hub or duplicate weights. Splash's compiled weight cache may be relocated through `SPLASH_WEIGHT_CACHE`; no cache directory is deleted or silently moved. The model snapshot remains external to the app bundle. Paperclip checks free disk before launch and returns an actionable failure when storage is too low.

When `SPLASH_WEIGHT_CACHE` names an existing absolute directory, the 8 GiB check applies to that volume. V2 still needs 0.5 GiB free for its private metadata. Without that setting, both checks apply to V2's data volume. The setting must be present in V2's environment before launch.

The existing Paperclip-owned five-tool coding loop and single-run queue remain intact. Its model requests and environment tests now address only the app-owned Splash server. Claude, OpenAI, and OpenCode account bindings are unchanged. The local adapter never receives their credentials.

V2 configures both the server context ceiling and the requested output ceiling at 85% of the model's native 262,144 tokens: 222,822 tokens each. Chat requests count the exact rendered prompt through Splash's `/apply-template` and `/tokenize` endpoints, then request no more than the context remaining after that prompt. This avoids Splash's HTTP 400 for `prompt + max_tokens > context` while preserving the requested maximum. Incomplete responses still fail closed before any partial tool call is executed.

## Qualification

Focused tests cover relocated runtime imports, offline launch arguments, model/port identity, startup failure, concurrent Start calls, Stop while busy, no download, and unchanged paid-provider routing. A live check requires at least 8 GiB free disk and no other loaded local LLM, then a disposable task through the V2 app. The currently running V2 process must not be restarted while another agent run is active.

Live qualification with the operator: free enough disk without removing the cached weights, finish active V2 runs, close or unload Bionic's model, rebuild and relaunch V2, press **Start Splash**, verify exact model readiness, delegate a disposable task to a Splash agent, inspect its tool and activity ledger, then press **Stop Splash** after the run finishes. The older LM Studio-backed E2E task does not qualify the app-owned runtime.

## CTO task failure and longer private turns

On `SPL-6`, CTO run `86b0bf82-dab1-4ea0-a675-6e2312171ef6` exhausted the original 2,048-token output cap after read-only tool calls. The adapter rejected its incomplete answer. At the operator's request, V2 now sets context and requested output ceilings to 85% of the model's native 262,144 tokens, or 222,822. Run `9a97b519-9b59-4b3d-888f-d31e5b5db002` showed why Chat cannot request that full output alongside a nonempty prompt: Splash returned HTTP 400 before any tool call. The adapter now renders and tokenizes each text prompt through Splash's loopback API and requests only the context that remains.

Run `f92c5c88-6eb2-4d29-adaa-1a49ad40d798` passed prompt sizing and completed read-only tools, then spent five minutes decoding without response headers. Node's default Undici header deadline cancelled that turn after roughly 12.8K generated tokens. The Chat call now uses a scoped Undici dispatcher; each model turn is bounded to 25 minutes, below Splash 1.0.2's 30-minute request ceiling. A multi-turn local run and its FIFO queue have separate two-hour bounds. It keeps the same local model, one-run queue, and no paid-provider fallback. The user explicitly accepts slower local work for privacy. All three failed CTO attempts were reconciled through Paperclip's board evidence path only after verifying no task mutation was recorded. This branch's latest live bundle was updated with the transport change; the subsequent CTO continuation is tracked separately from these source changes.

Long non-streaming generations previously left the UI showing the last completed tool after the 90-second live-status TTL expired. The adapter now refreshes its generation status every 15 seconds. It measures the delta of Splash's model-wide `metrics.decode_output_tokens` from the start of each turn, and shows an approximate generated count with the exact prompt-token count and requested output allowance. Another client on the same loopback server could contribute to the model-wide counter, so the UI labels the generated count approximate; reasoning tokens also mean it is not a forecast of final visible text.

For future turns, the adapter reads Splash's Chat stream and keeps only a short rolling reasoning tail in memory. The live status combines that excerpt with token counts, allowing the board operator to see whether the model is repeating itself. The server's existing status redactor applies before live publication, and the reasoning excerpt is never appended to the durable run log. Streamed tool-call deltas are assembled but never executed until a complete final marker and normal tool validation succeed. This does not recover an in-flight generation that times out; it makes its progress inspectable while it runs.

The first 25-minute CTO continuation saved a playable `index.html` before its whole-run deadline. Board browser checks confirmed a win, draw, reset, endgame move lock, and a 375px layout; the file was attached to `SPL-6` as the primary artifact work product. The failed run's final generation remains unverified. Future local runs have a separate 25-minute limit per model turn and a two-hour whole-run bound. The role-aware local prompt asks CTO/CEO coordinators to inspect existing children, create no more than three narrow child issues with explicit assignees and acceptance checks, and record the routing choice before implementing child work. Local/private details stay with app-managed Splash agents unless the board explicitly approves a named remote AI Connection.

The streamed adapter was qualified through disposable task `SPLA-2`, run `deb358df-887d-4c9d-887d-328e13856164`: it read the workspace, wrote the requested one-line file, ran Git status, commented, and marked the task done. The live status displayed 1,829 prompt tokens and a 220,993-token output allowance. Its durable run log contains tool events and no reasoning text. This short run finished before the 15-second rolling-excerpt update; synthetic stream tests verify excerpt handling and incomplete-stream tool safety, but a long live excerpt remains to be observed. `SPL-6` remains blocked with an explicit board-owned local-review action because completing it would wake the parent CEO on a remote GLM/OpenCode account. The operator requested local review first.
